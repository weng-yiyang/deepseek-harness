# 个人自用 · 免签名 / 免公证运行方案

> 适用前提：软件只给你自己在这一台（或少数几台你自己的）机器上用，不对外分发给同事/客户。
> 结论先行：**完全不需要购买代码签名证书、不需要 Apple 公证**，零成本即可跑起来。

---

## 一、为什么"对外分发"才需要签名

SmartScreen（Windows）/ Gatekeeper（macOS）的设计目标是拦截"从互联网下载的、发布者身份未知的"软件，保护普通用户。

- **你自己写、自己跑、不发给别人**：系统只是"不认识你这个发布者"，放行一次即可，本就不要求你付费认证。
- **你发给别人**：别人机器也会拦，且批量传播会被当成"未知发布者广泛扩散"，此时才必须签名 + 公证来建立信任。

所以：自用 = 免签名；分发 = 必须签名公证（见 [`docs/跨平台安装包方案.md`](跨平台安装包方案.md)）。

## 二、三平台免签名放行方式

| 平台 | 免签名能否跑 | 首次放行动作 | 备注 |
|---|---|---|---|
| Windows | ✅ 能 | NSIS 安装时 SmartScreen 弹窗 →「详细信息」→「仍要运行」 | Electron 自身二进制已由 GitHub 签名，仅"你的打包壳"未签名 |
| macOS | ✅（仅本机） | 方式 A：`xattr -dr com.apple.quarantine /Applications/<App>.app` 清隔离后双击；方式 B：本机 ad-hoc 签名（免费，不需 $99，见第四节） | ad-hoc 仅本机有效，换机器失效 |
| Linux | ✅ 能 | 无门槛，AppImage / .deb 直接运行 | 三平台里最省心 |

## 三、推荐的两种自用姿态

### 姿态一：不打包，直接本机运行（最干净，零拦截）★ 推荐

桌面端本质是个 Electron 工程，开发模式启动即 `electron .` —— 由 Electron 自带的（已签名）二进制去拉起你**本地未打包**的代码，系统根本不会拦你。

```bash
pnpm install
pnpm --filter @deepseek-ai/dsh-web-frontend run build
pnpm --filter @deepseek-ai/dsh-desktop run dev
```

- 优点：永远不需要签名；改代码即时生效；无安装包、无弹窗。
- 代价：不是"双击安装包"的体验，需要本机已装好 Node + 依赖（你环境已具备）。

### 姿态二：出免签名安装包，首次手动放行（有安装体验）

用现有 electron-builder，确认签名/公证开关为 `false`（当前默认已是），本地直接构建：

```bash
pnpm --filter @deepseek-ai/dsh-desktop run dist:win     # Windows → NSIS .exe
pnpm --filter @deepseek-ai/dsh-desktop run dist:mac     # macOS → .dmg（不公证）
pnpm --filter @deepseek-ai/dsh-desktop run dist:linux   # Linux → AppImage / .deb
```

- Windows：安装时 SmartScreen 弹一次，点「仍要运行」即可。
- macOS：装完后执行下面任一行再双击：
  ```bash
  xattr -dr com.apple.quarantine "/Applications/DeepSeek Harness.app"   # 应用名以 electron-builder.yml 的 productName 为准
  # 或右键 App → 打开 →「仍要打开」，将其加入本机白名单
  ```
- Linux：直接双击 AppImage 或 `sudo dpkg -i *.deb`。
- 注意：**每次更新版本后，放行动作需重做一次**（新哈希 = 新的"未知发布者"）。

## 四、进阶：让 macOS 一次到位（免费 Apple ID 自签）

不需要 $99 付费开发者计划。最简单是 **ad-hoc 签名**（用本机标识 `-`，不联网、不认证）：

```bash
codesign --force --deep --sign - "/Applications/DeepSeek Harness.app"
```

效果：本机永久放行，Gatekeeper 不再拦。限制：仅当前机器有效，换机器/分发给别人仍不行。

若你已有免费 Apple ID 并在 Xcode 登录，也可在「账户」里生成个人开发证书后做正式本机签名，效果同上、更规范，但仍不能跨机器信任。

---

## 五、进阶：让 Windows 不再弹 SmartScreen（可选）

1. **自签证书 + 导入信任根（仅本机信任）**：用 PowerShell 生成自签名证书并导入「受信任的根证书颁发机构」，再用它对安装包/目录签名 → 本机不再弹窗。
   ```powershell
   New-SelfSignedCertificate -Subject "CN=MyLocalDev" -Type CodeSigning -CertStoreLocation Cert:\CurrentUser\My
   # 导出 .pfx → 导入「受信任的根证书颁发机构」→ 用 signtool 对该 exe 签名
   ```
2. **关闭 SmartScreen（降安全，不推荐）**：Windows 安全中心 → 应用和浏览器控制 → 关闭 SmartScreen。

个人单机想要"零弹窗"可用方案 1；否则每次点一次「仍要运行」也就一秒钟的事。

## 六、与对外分发方案的区别（回顾）

| 维度 | 个人自用（本方案） | 对外分发（[`docs/跨平台安装包方案.md`](跨平台安装包方案.md)） |
|---|---|---|
| 代码签名证书 | 不需要 | Windows 必买（EV/标准）、macOS 需 $99 计划 |
| Apple 公证 | 不需要 | 必须 |
| 首次运行 | 自己放行一次 / 直接 dev 跑 | 用户无感（已信任） |
| 自动更新 | 可关（或本机自托管） | 必须签名否则更新被拦 |
| 成本 | ¥0 | 年费证书 |

---

## 七、一句话建议

你只要自己用 → 走「姿态一（dev 直跑）」最省事，或「姿态二（免签名包 + 首次放行）」要安装体验，**证书一分钱都不用花**。等哪天要发给同事/客户，再买证书、开 CI 签名（[跨平台安装包方案](跨平台安装包方案.md)已就绪）。
