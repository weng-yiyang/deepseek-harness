# DeepSeek Harness 桌面端 · 跨平台安装包方案

> 目标：Windows / macOS / Linux 三个平台各出一个"可分发、最好能双击即用"的原生安装包。
> 本文只讲"做什么"，不展开代码；落地配置已在 `electron-builder.yml` 与 `.github/workflows/build-desktop.yml` 中具备。

---

## 1. 目标产物矩阵

| 平台 | 主推格式 | 其他可选 | 产出命令 | 双击即用门槛 |
|---|---|---|---|---|
| **Windows** | `NSIS` 安装包 `.exe` | Portable 单文件 `.exe` | `dist:win` | 需代码签名，否则 SmartScreen 拦截 |
| **macOS** | `.dmg` | `.zip` | `dist:mac` | **必须** Developer ID 签名 + 公证，否则 Gatekeeper 拦截 |
| **Linux** | `AppImage`（跨发行版通用） | `.deb`（Debian/Ubuntu）、`.rpm`（RHEL/CentOS） | `dist:linux` | 无门槛，直接运行 |

> 一个平台一个安装包的最简组合：**Windows `.exe` + macOS `.dmg` + Linux `.AppImage`**。
> 若要覆盖更多 Linux 发行版，追加 `.deb` / `.rpm`。

---

## 2. 三种产出方式（任选 / 组合）

### A. 本机各自打包
在对应操作系统上执行：
```bash
pnpm --filter @deepseek-ai/dsh-desktop run dist:win     # 必须在 Windows 上
pnpm --filter @deepseek-ai/dsh-desktop run dist:mac     # 必须在 macOS 上（签名/公证只能 Mac）
pnpm --filter @deepseek-ai/dsh-desktop run dist:linux   # 必须在 Linux 上
```
- 优点：直观、调试方便。
- 缺点：需要三台不同系统的机器；macOS 签名公证离不开 Mac。

### B. CI 矩阵一键出三端（**推荐**）
仓库已有 `.github/workflows/build-desktop.yml`，在 `windows-latest` / `macos-latest` / `ubuntu-latest` 三个 runner 上**并行**构建：
- 触发：`git push` 打 `v*` tag，或仓库 Actions 页手动 `workflow_dispatch`。
- 行为：自动 `install(hoisted) → build:lib → web build → assemble-runtime → electron-builder --<平台>`；产物上传 Artifact，推 tag 时额外发到 GitHub Release。
- 证书 Secrets 缺失时**自动降级为未签名包**，仍可出包自测。

### C. 混合（本地自测 + CI 发布）
本地用未签名包自测功能；确认无误后推 tag，由 CI 出**签名** Release 正式发布。

## 3. 构建链（已具备，无需再写）
```
pnpm install (Windows 加 npm_config_node_linker=hoisted)
  → pnpm run build:lib            # 后端 apps/cli/lib/bin.js
  → pnpm --filter @deepseek-ai/dsh-web-frontend run build   # 前端 apps/web/dist
  → pnpm --filter @deepseek-ai/dsh-desktop run assemble-runtime   # 归集 dist/runtime
  → electron-builder --win | --mac | --linux                      # 出安装包
```

## 4. 签名与信任（决定"能不能直接打开"）

| 平台 | 不签名后果 | 签名/公证方式 | CI 启用变量 |
|---|---|---|---|
| Windows | SmartScreen 红屏警告，用户需"仍要运行" | EV/OV 代码签名证书 | `CSC_LINK`(p12 base64) + `CSC_KEY_PASSWORD` |
| macOS | Gatekeeper 直接拦截，无法打开 | Apple Developer ID 证书 + 公证(notarize) | `MAC_CSC_LINK` + `APPLE_ID` + `APPLE_APP_SPECIFIC_PASSWORD` + `APPLE_TEAM_ID` |
| Linux | 无门槛，双击/命令行直接跑 | 无需 | — |

> `electron-builder.yml` 中 `win.sign` / `mac.notarize` 已设为 `false`，由 CI 用
> `--config.win.sign=true` / `--config.mac.notarize=true` 覆盖启用。

---

## 5. 代码签名证书准备（上线前必须，路线中的 P1/P2）

- **Windows**：向 DigiCert / Sectigo 等 CA 购买 OV 或 EV 代码签名证书 → 导出含私钥的 `.p12` → 转 base64 → 存 GitHub Secret `WIN_CSC_LINK`，密码存 `WIN_CSC_KEY_PASSWORD`。
  - EV 证书门槛高但 SmartScreen 信誉积累更快；OV 便宜但需积累信誉期。
- **macOS**：加入 Apple Developer Program（\(99/年）→ 钥匙串创建 **Developer ID Application** 证书 → 导出 `.p12` → 存 `MAC_CSC_LINK`；另需 `APPLE_ID`（开发者邮箱）、`APPLE_APP_SPECIFIC_PASSWORD`（App 专用密码）、`APPLE_TEAM_ID`。
- **内网/离线场景**：可用企业内 CA 自签，但每台终端需预先信任该根证书，体验差，仅推荐纯内网分发。

---

## 6. 分发与自动更新

- **公开分发**：GitHub Releases（CI 已接 `softprops/action-gh-release`，推 tag 自动上传三个安装包 + `latest.yml`）。
- **内网分发**：静态服务器托管安装包与 `latest.yml`，桌面端设 `DSH_UPDATE_URL` 指向该地址，`electron-updater`（已接入）即可自动检测并更新。
- **体积优化**：`assemble-runtime` 当前整份复制 `node_modules`，较大；生产建议改用 `pnpm deploy --filter @deepseek-ai/dsh --prod` 生成仅生产依赖的 `node_modules` 显著瘦身。

---

## 7. 实施路线（分步、可早出包）

- **P0 — 跑通全链路（现在就能做）**：CI 三平台未签名包先出，验证构建/打包链无误。配置已齐，缺 Secrets 时自动降级未签名。
- **P1 — Windows 签名**：购 Windows 证书 → 填 `WIN_*` Secrets → 出签名 `.exe`，消除 SmartScreen。
- **P2 — macOS 签名+公证**：购 Apple 开发者 → 填 `MAC_*` / `APPLE_*` Secrets → 出可双击打开的 `.dmg`。
- **P3 — 分发与更新**：配 GitHub Releases 或内网 `DSH_UPDATE_URL`，开启自动更新；按需加 Linux `.rpm`、多架构（arm64）。

**已就绪**
- `electron-builder.yml`：三端 target（nsis / dmg / AppImage+deb）已配。
- `.github/workflows/build-desktop.yml`：三平台并行构建矩阵，Secrets 缺失自动降级未签名，推 tag 发 Release。

2. 打一个 `v*` tag 推送到仓库，CI 自动出三端安装包。

- Linux 追加 `.rpm`（改 `electron-builder.yml` 的 `linux.target`）。
