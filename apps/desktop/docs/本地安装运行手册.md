# DeepSeek Harness 桌面端 · 本地安装运行手册

> 适用对象：想在本机把 `deepseek-harness` 的 `dsh web`（Node 后端 + Vite 前端）跑起来的人。
> 包含两种入口：**独立 Web**（浏览器访问）与 **桌面客户端**（Electron 封装窗口）。
> 全文把仓库根目录记作 `<repo>`，请替换成你的实际路径（例如 `D:\Desktop\WorkBuddy_WorkSpace\2026-08-08-20-53-17\deepseek-harness`）。

---

## 0. 前置结论（先读这段）
- Windows / macOS / Linux 都能跑；**Windows 没有原生 `dsh` 二进制**，必须 `DSH_RUNTIME_MODE=node`（用 Node 跑后端）。
- **Node 版本必须 `^22.19.0 || >=24.0.0`**（当前验证环境是 v22.22.2）。低版本启动即报错。
- 包管理器用 **pnpm 11.7.0**（仓库 `packageManager` 字段锁定，用 corepack 拉齐）。
- Windows 安装依赖时务必 `npm_config_node_linker=hoisted`，否则会踩 symlink 权限 / 空目录坑。
- 本地运行后端前必须 `pnpm run build:lib`（生成 `apps/cli/lib/bin.js`）；用根 `pnpm dsh` 直接跑源码可免构建。

## 1. 环境前置

| 依赖 | 要求 | 说明 / 安装 |
|---|---|---|
| Git | 任意新版本 | 仅用于 clone 仓库 |
| Node.js | `^22.19.0 \|\| >=24.0.0` | 推荐 22.22.x 或 24.x；Windows 用 [nodejs.org](https://nodejs.org) 安装包 |
| pnpm | `11.7.0` | `corepack enable` 后 `corepack prepare pnpm@11.7.0 --activate`；或 `npm i -g pnpm@11.7.0` |
| 构建工具 | 随仓库装 | `tsc` / `tsdown` / `vite` / `tsx` 均在 `devDependencies`，`pnpm install` 自动带入 |
| Electron | 随 desktop 包装 | 在 `apps/desktop` 的 `devDependencies`，`pnpm install` 自动带入 |

**Windows 专属注意**
1. 无原生 `dsh` 二进制 → 后端只能 `DSH_RUNTIME_MODE=node`。
2. HMR 插件要求 Node 带 `--expose-internals`（已内置在启动脚本里，别手敲时漏掉）。
3. 建议开启「开发者模式」或以有 symlink 权限的账户安装，配合 `hoisted` 最稳。

## 2. 获取源码
```bash
git clone <仓库地址> deepseek-harness
cd deepseek-harness          # 即 <repo>
```

## 3. 安装依赖
```bash
# Windows（关键：hoisted linker 规避 symlink EPERM / 空目录）
npm_config_node_linker=hoisted pnpm install

# macOS / Linux
pnpm install
```
- **pnpm 版本不对**：仓库锁了 `11.7.0`。若报版本守卫，先 `corepack enable && corepack prepare pnpm@11.7.0 --activate`。
- **`postinstall`（install-lefthook）失败**：这步只是装 git hook，不影响运行。可 `pnpm install --ignore-scripts` 重试，或忽略该报错。
- 安装完成后 `node_modules` 很大且含大量包；桌面端打包时会再做一次归集（见第 8 节）。

## 4. 构建（本地运行前必须做一项）
| 你要做的事 | 命令 | 产出 |
|---|---|---|
| 构建后端（**独立 Web / 桌面端都需**） | `pnpm run build:lib` | `apps/cli/lib/bin.js` 等 |
| 构建前端页面（独立 Web 模式 A / 打包需） | `pnpm --filter @deepseek-ai/dsh-web-frontend run build` | `apps/web/dist/` |
| 前端热更新（桌面端模式 B，不需 build） | `pnpm --filter @deepseek-ai/dsh-web-frontend run dev` | 起 Vite dev server :5173 |

> 提示：想**免构建**直接跑后端源码，可用根脚本 `pnpm dsh ...`（= `node --import tsx/esm apps/cli/src/bin.ts`）。但 Windows 下它缺 `--expose-internals`，会触发 HMR 报错，故本地推荐用下面的显式命令或 `start-dsh-web.cmd`。

## 5. 运行方式

### 5.1 独立 Web（浏览器访问，不封装桌面）
**方式一：双击脚本（最简单，已验证）**
直接运行仓库根的 `start-dsh-web.cmd`（内容已含 `--expose-internals` + `DSH_RUNTIME_MODE=node` + 端口 3080），然后浏览器打开：
```
http://127.0.0.1:3080
```
> 该脚本默认加载**已构建**产物（`apps/cli/lib/bin.js`），所以先执行过第 4 节的 `build:lib`。要对话能力，取消脚本里 `REM set DEEPSEEK_API_KEY=sk-...` 那行注释并填 key。

**方式二：手动命令（免 build，直接跑源码）**
```bash
cd <repo>
set DSH_RUNTIME_MODE=node
node --expose-internals --import tsx/esm apps/cli/src/bin.ts web
# 浏览器同样访问 http://127.0.0.1:3080（默认端口，DSH_WEB_PORT 可改）
```

### 5.2 桌面客户端 · 模式 A（无 HMR，加载生产构建）
```bash
cd <repo>
pnpm --filter @deepseek-ai/dsh-web-frontend run build   # 先构建前端
pnpm --filter @deepseek-ai/dsh-desktop run dev           # 启动 Electron 窗口
```
- 窗口内加载的是 `dsh web` 同端口提供的完整页面（含前端），无热更新。
- 后端子进程由 `main.js` 自动拉起（随机空闲端口 + `--expose-internals` + `DSH_RUNTIME_MODE=node`），无需手动起。

### 5.3 桌面客户端 · 模式 B（Vite HMR 热更新，推荐开发用）
前端由 Vite dev server 提供（改代码即时生效），后端 API 仍由 `dsh web` 子进程提供（开发模式固定在 `3080`）。

**步骤 1**：给前端仓库加 proxy（让 `/api` 等请求转发到后端 3080）。编辑 `<repo>/apps/web/vite.config.*`：
```ts
export default defineConfig({
  server: {
    port: 5173,
    proxy: {
      '/api': 'http://127.0.0.1:3080',
      '/ws':  { target: 'http://127.0.0.1:3080', ws: true },
      // 按 dsh web 实际 API 前缀调整路径
    },
  },
});
```

**步骤 2**：两个终端
```bash
# 终端 1：起 Vite dev server
pnpm --filter @deepseek-ai/dsh-web-frontend run dev

# 终端 2：启动 Electron，指向 dev server
#   Windows (PowerShell)
$env:DSH_DESKTOP_DEV_SERVER="http://localhost:5173"; pnpm --filter @deepseek-ai/dsh-desktop run dev
#   macOS / Linux
DSH_DESKTOP_DEV_SERVER=http://localhost:5173 pnpm --filter @deepseek-ai/dsh-desktop run dev
```
- `main.js` 检测到 `DSH_DESKTOP_DEV_SERVER` 后会加载该地址并自动打开 DevTools；改 Vite 代码即实时热更新。

## 6. 接入对话能力（可选）
仅当你要用 Web UI 真正对话时才需要：
```bash
# 独立 Web：在 start-dsh-web.cmd 取消注释并填值，或命令行：
set DEEPSEEK_API_KEY=sk-xxxxxxxx

# 桌面端：在 dev 命令前设置
$env:DEEPSEEK_API_KEY="sk-xxxxxxxx"; pnpm --filter @deepseek-ai/dsh-desktop run dev
```
启动 Web UI 本身**不**要求 key，只有发起模型对话时才用。

## 7. 数据与配置目录
- **独立 Web / 命令行版**：profile 默认在 `~/.dsh`（Windows：`%USERPROFILE%\.dsh`）。
- **桌面客户端**：通过 `DSH_HOME` 隔离到应用专属目录 `userData/dsh-home`，与命令行版互不干扰。
- 想让桌面端共用同一份数据：启动前设
  ```bash
  $env:DSH_HOME="$env:USERPROFILE/.dsh"   # Windows
  # 或 macOS/Linux: export DSH_HOME="$HOME/.dsh"
  ```

## 8. 打包安装包（出可分发包）
```bash
cd <repo>
pnpm --filter @deepseek-ai/dsh-web-frontend run build   # 先构建前端
pnpm --filter @deepseek-ai/dsh-desktop run dist:win      # 或 dist:mac / dist:linux / dist
```
- `dist` 会先跑 `assemble-runtime`（把 `node_modules` 解引用 + `apps/web/dist` 归集到 `dist/runtime`），再交 electron-builder。
- 产物在 `apps/desktop/release/`：`DeepSeek Harness-<ver>-setup.exe`（Windows NSIS）/ `.dmg`（macOS）/ `AppImage` + `.deb`（Linux）。
- **代码签名**：本地默认不签名（Windows SmartScreen / macOS Gatekeeper 会拦截）。正式发布请用 CI（见 `apps/desktop/README.md` 的「CI 自动构建与代码签名」）。

## 9. 故障排查（FAQ）

| 现象 | 原因 | 解决 |
|---|---|---|
| `EPERM` / `node_modules` 大量空目录 | Windows symlink 权限不足 | 安装时加 `npm_config_node_linker=hoisted pnpm install` |
| `HMR service requires --expose-internals` | Node 启动缺该 flag | 用 `start-dsh-web.cmd` 或手动加 `node --expose-internals ...` |
| `command not found` / 提示无原生 `dsh` | Windows 无原生二进制 | 设 `DSH_RUNTIME_MODE=node` |
| `Cannot find module '@deepseek-ai/dsh'` | 没构建后端 | 先 `pnpm run build:lib` |
| 端口被占用 | 3080 已被占 | 独立 Web 改 `DSH_WEB_PORT`；桌面端 HMR 模式固定 3080（确保空闲或改 `main.js` 的 `DEV_SERVER_PORT`） |
| Node 报错引擎不符 | Node 版本 < 22.19 | 升级到 22.19+ / 24.x |
| `postinstall` 失败 | lefthook 装不上 | 不影响运行，可 `pnpm install --ignore-scripts` |
| Electron 窗口空白 | 前端没 build 或 dev server 没起 | 模式 A 先 `build`；模式 B 确认 Vite 已在 5173 且 proxy 配好 |
